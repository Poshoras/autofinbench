## 5. 学到的东西

1. **回测是必要的**：30 道里 5 道原答案有实质性错误，最常见的是同一题内两年口径不一致（024、027）。
2. **原文定位能直接诊断错误来源**，例如 001 的 2,687 自动定位到现金流量表的"支付的利息"。
3. **淘汰都是因为信息源消失**：公司被收购、科目停止披露、披露要求取消。
4. **科目名会漂移**（JPM、Nike），所以需要"找不到 → 搜索替代 → 原文确认"的修订能力。
5. **同一家公司里"同名不同义"**：026 的 FCF 是"经营现金流 − 资本开支"，030 用的是 P&G 的调整后 FCF。新题都已经在题干里写明。
6. **有些数据不在 XBRL 里**（员工数、非 GAAP 指标），需要从正文取数；这类数字只有一个来源，我们尽量用组成项相互核对（030）。

## 6. 题干与 GT 的修订（2026-11-20，共 3 次）

1. **不写公式**：题干写出公式，等于把推理过程交给了受测模型。
2. **只改时间**：新题 = 原题只替换年份。问题是原题本身信息不全。
3. **成对、自足、得分点与题干一致（当前版本）**。外部检查发现：只改时间的题干缺公司、财年、必答指标或口径，联网模型搜错了公司、用了季度数据、答了不在得分点里的指标；得分点和题干要求也对不上。修订后：

| 规则 | 做法 | 自动检查 |
|---|---|---|
| 旧题、新题只差时间 | 先写旧题完整版（原期间），再只替换时间表达生成新题 | 去掉时间表达后两题完全一致（15/15） |
| 题目自足 | 题干写明公司、财年及截止日、必答指标、单位、关键口径（如"平均余额""EBIT 口径""NIKE Brand 收入"），但不写计算步骤 | 公司名必须出现；题干不得含 `=`、`/`、divided by 等 |
| 得分点 = 题干要求 | 题干没要求的不评（如 006 的 NIKE Brand 总额、027 的 DIO/DSO/DPO 都去掉了） | 每个得分点都要在题干中找到对应说法（15/15） |
| 不再用替代口径 | 口径已写进题干，删除所有"也接受"的答案 | — |
| 旧题答案更正 | 旧题标准答案按同一口径、用原期间数据重算 | — |

`new_benchmark_agent.csv` 的主要列：`old_question` / `old_ground_truth` / `old_answer_json`（旧版），`question` / `ground_truth_answer` / `answer_json`（新版），`seed_original_question`（SecQue 原题）。GT 的格式是"答案 + 带实际数字的算式 + 所用数据"，全部由代码生成。

### SecQue 原论文的评分方法（供设计评测参考）

- 模型拿到题目和相关年报页面（context）后自由作答。
- 裁判模型（原文用 GPT-4o）对照 GT 打 0 / 1 / 2 分（错 / 部分对 / 全对），同一个答案打 5 次，分数相加：≥6 记 2 分，4–5 记 1 分，<4 记 0 分。
- 报告两个指标：Strict Accuracy（2 分的比例）和 Normalized Accuracy（2 分记 1、1 分记 0.5 后取平均）。
- 裁判与金融专家人工打分的一致性：F1(2) = 0.85；判断"全对"较准，区分"部分对"和"错"较弱。
- 原文承认"有些题不止一种正确算法"，但没有处理。我们的 `accepted_variants_json` 正好可以补上这一点。

## 7. 局限

- 需要判断的步骤由同一个 Claude 会话完成，没有换模型做审校。
- 旧版题目的输入数据只经过 XBRL 一条通路（原文核对只做了新版）。
- 第二轮"自动通过"的题没有经过逐题人工判断，需要最后的抽样人工审核兜底。
- 生成成本只记录了时间，没有统计 token。
- B 组（简单提示词）还没跑；"附原文作答"所需的新原文片段还没生成。
