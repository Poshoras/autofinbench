## 2. Pipeline（6 步）

| 步骤 | 做什么 | 由谁完成 |
|---|---|---|
| ① 学模式 | 把原题拆成解题模板：比较结构、运算、每个数据项（科目名 / 哪张表 / 时点或区间）、输出格式；在原题自带原文里逐个定位 GT 中的数字 | 模板：Claude；定位：代码 |
| ② 回测 | 用模板 + 原文件 XBRL 重算原题答案；输入对不上时自动诊断"原题这个数其实是哪个科目" | 代码，结论由 Claude 写 |
| ③ 规划 | 选目标文件（同类文件的最新一期），逐项检查数据在新文件中是否可得；不可得 → 修订或淘汰 | 可得性：代码；决策：Claude |
| ④ 取数计算 | 从目标文件 XBRL 取数，代码计算 | 代码 |
| ⑤ 出题 | 换期间、补全公司名/范围/口径；答案由 ④ 的结果自动填入（不手抄数字） | 题干：Claude；答案：代码 |
| ⑥ 审校 | 每个输入数字必须在目标文件**原文**中、对应科目名附近出现（与 XBRL 是两条独立通路）；检查题干是否泄露答案、数值是否靠近舍入分界；不通过 → 退回修订（≤2 轮） | 检查：代码；结论：Claude |

## 5. 这一轮学到的东西

1. **回测是必要的**：10 道里 3 道的原答案有数值/口径错误，另 3 道的叙述结论有错。不回测会把这些错误带进新题。
2. **原文定位能直接诊断错误来源**：例如 001 的 2,687 自动定位到现金流量表 "Cash paid for interest"。
3. **淘汰原因都是"信息源消失"**：科目停止披露、披露要求取消、公司被收购。这些只能靠工具查实际文件发现，单靠模型判断发现不了。
4. **科目名会漂移**：JPM 的利息费用 XBRL 标签改了、Nike 的利息行名称变了。agent 需要"找不到 → 搜索替代 → 原文确认"的修订能力。
5. **开放/叙述题可以形式化**：003、004 改写为指定指标 + 是/否判断后可自动判分。

## 6. 局限（如实说明）

- 需要判断的步骤（学模式、规划决策、写题、审校结论）由同一个 Claude 会话完成；审校的独立性目前只靠"XBRL 与原文两条通路"的代码核对，没有换模型。
- 生成成本（token、时间）没有统计；正式用 API 自动化时要记录。
- 前 10 道不是随机样本。
- **B 组（简单提示词）还没跑**：它必须在看不到 C 组答案的新上下文里生成，才算公平（见 `baseline_B_prompt.md`）。
- 新题对应的"新原文片段"（对应 SecQue 的 `context_*` 列）还没生成，"附原文作答"的评测需要它。
