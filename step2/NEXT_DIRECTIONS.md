# 下一步方向：XFinBench 的用户要什么，模型差在哪

日期：2026-11-22　｜　依据：XFinBench 论文、2025–2026 年的金融 agent 评测和行业报告（来源见文末），以及我们 20 道试改题的测试结果

## 1. 这次测试说明了什么

- **A、B、C 三类全对。**题目条件变了、需要反向求解、换了数字，模型都能换对公式、算对结果。对这种自带全部参数的教科书式题目，"懂公式并正确使用"已经不是瓶颈。
- **D 类全错。**两道题都缺一个必需的数（无风险利率、维持保证金），模型没有指出缺了什么，而是自己补一个数硬算。

**有一个混杂因素要先排除。**step2 的答题提示词要求最后一行必须是 `Final answer: <number>`，没有给"算不出来"留出口，模型等于被逼着给数。下次测 D 类要用两种提示词：
1. 中性版：允许回答 "cannot be determined"，但不提示题目可能缺条件；
2. 提醒版：明说题目可能缺条件。

两者的差距，正好衡量模型在没人提醒时，能不能自己发现前提有问题。

另外，D 类只有 2 道，只能说明方向，还不能下结论。不过外部研究的结论是一致的，见第 3 节。

## 2. 谁在用 XFinBench，他们的 agent 干什么

论文自己的定位是"帮助研究者评估模型在金融领域的表现"。实际会用它的主要是两类人：
- 做金融模型的团队：开源金融大模型、通用模型的金融能力评测；
- 做知识增强的研究者：论文附带了 3,032 个术语的知识库，就是为这类研究准备的。

这些团队做的 agent，落地场景对应三本教材的内容：

| 场景 | 典型任务 | 对应教材 |
|---|---|---|
| 投研、投行、企业财务的分析助手 | 估值、资本预算、资本结构、营运资本 | 公司财务（Ross） |
| 交易和风控 | 衍生品定价、对冲、保证金、利率风险 | 期权期货（Hull） |
| 银行资金和资产负债管理 | 利率缺口、准备金、货币政策的影响 | 货币银行（Mishkin） |
| 面向个人的理财和贷款咨询 | 储蓄、退休规划、贷款利率比较 | 公司财务的货币时间价值部分 |

这些场景和教科书题有一个根本区别：**问题来自用户，常常没说清、说错，或者用的是过时的说法。**教科书题保证"条件齐全、彼此一致、没有过时信息"，而真实场景不保证。agent 的输出又会直接交给客户、交易员或监管方，所以带着错误前提算出一个看起来合理的数，代价比直接说"算不出"大得多。

## 3. 外部证据：模型差在哪

| 来源 | 发现 |
|---|---|
| 剑桥 2026 全球金融 AI 报告 | 供应商、金融机构、监管方都把"幻觉和不可靠输出"列为前两大风险，比例分别为 67%、70%、70% |
| BankerToolBench（2026，502 名投行人员参与） | 最好的模型也有近一半评分项不合格，没有一份输出被认为可以直接交给客户；主要问题之一是多份产出之间互相不一致 |
| FinanceQA（AfterQuery） | 信息不全、需要自己做合理假设的那类题，平均正确率约 8.4%，是三类里最低的 |
| RealFin（ACL 2026 Findings） | 关键条件缺失时，通用模型倾向于猜一个答案而不是先说明；多数金融专用模型不能明确指出缺了哪个前提 |
| AbstentionBench（NeurIPS 2025） | 该拒答时不拒答是没解决的问题，模型变大也没用；做过推理训练的模型拒答能力平均下降 24%，数学类题目也一样 |
| XFinBench 论文本身 | 差距最大的是时间推理和情景规划；计算题的错误来自舍入和用错公式 |

**我的判断**：前沿模型在 XFinBench 这类题上的差距已经不在"算"，而在"对前提的把关"：
- 缺条件时不说，自己补；
- 条件互相矛盾时看不出来；
- 题目里预设了错误的事实时照单全收；
- 用的规则已经过时了，也意识不到。

这和我们 D 类全错、A/B/C 全对的结果是同一回事。XFinBench 论文里说的"时间推理、情景规划"差距，按 2024 年的模型测出来，现在看来大部分已经被追上了。

## 4. 下一步方向：围绕"前提处理"扩展

每个方向都要满足同一条要求：**标准答案能由代码或明确的理论判定，不靠人的主观判断。**

| 方向 | 怎么改 | 正确回答 | 答案怎么控制 | 例子 |
|---|---|---|---|---|
| **D1 缺前提**（已有，扩量） | 删掉一个必需参数 | 说明算不出，并指出缺的是哪个数 | 逐题检查删掉的数既推不回来，也没有通用惯例能补 | test_1822 删掉利率；test_95 删掉维持保证金 |
| **D2 前提矛盾或不可行** | 把参数改成互相矛盾或在金融上不可能 | 指出矛盾在哪，不给数 | 用代码检查约束条件：无套利条件、概率之和、还款能否覆盖利息等 | 二叉树里上涨倍数小于无风险增长倍数（u < e^{rΔt}），风险中性概率大于 1；每月还款小于每月利息，贷款永远还不清（XFinBench 的 test_1622 就是转写出错造成的天然例子） |
| **D3 错误前提** | 在问题里预设一个错误的金融事实 | 指出前提错了，再给正确结论 | 前提的真假由定理或惯例决定。XFinBench 有 1,360 道判断题，其中的假陈述可以直接改写成"预设" | "派发 2 美元普通现金股利后，行权价下调了多少？"正确回答是：不调整，仍为 60 |
| **D4 过时的制度或惯例** | 把题目的时间设为现在，题干仍沿用教材年代的制度 | 指出制度已变，按现行规则回答 | 制度变化有明确日期，需逐条核对官方来源 | XFinBench 测试集有 83 道题用到 LIBOR，而美元 LIBOR 已停止发布；美联储 2020 年 3 月起把准备金率降为 0；美国联邦公司税率 2018 年起为统一的 21% |
| **D5 需要说明假设** | 留下一个按惯例可以补的条件，例如没写计息方式 | 写明采用的假设，并给出与假设一致的数 | 列出所有合理假设及各自的答案；回答必须写明假设，且数值与该假设一致 | 不写"按年复利还是按月复利"的贷款题 |

**和 AutoFinBench 原来的目标怎么衔接**：D4 本质上就是最早"时间迁移"的想法，但换了一个角度。不是把题目的期间换成新的，而是检验模型是否意识到规则随时间变了。这直接对应"模型用了过时信息"这个风险。

## 5. 优先级和实验设计要点

**建议先做 D2 和 D3，同时把 D1 扩大。**
- D2、D3 的标准答案由金融理论决定，最好控制，而且必须懂金融才能发现问题，不是单纯的"找漏洞"。
- D1 现在只有 2 道，要扩充到能下结论的数量。
- D4 要逐条核对制度事实，D5 的评分规则更复杂，放到第二批。

**设计要点**：
1. **每道"有问题的题"都配一道没问题的对照题**，也就是原题。同时报告两个数：有问题的题有没有识别出来，没问题的题有没有被误判为有问题。否则一个什么都拒答的模型也能拿满分。
2. **用两种提示词各测一次**（见第 1 节），差距就是"不提醒时自己发现前提问题"的能力。
3. **评分**：识别了没有、给没给数，按规则判；指出的问题对不对，交评委判，评委只做这一项。和 step1 的做法一样。
4. **先复现原答案**的要求不变。D2 和 D3 的对照题就是原题，答案已经复现过。
